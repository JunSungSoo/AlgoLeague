# 홈 대시보드 데이터 명세

홈 화면은 예시 값이나 브라우저 저장소를 사용하지 않고 `GET /api/dashboard`의 인증 사용자 데이터만 표시한다. `DATABASE_URL`이 없거나 조회에 실패하면 가짜 값으로 대체하지 않고 오류와 수집 방법을 보여준다.

| 화면 데이터            | 원천                              | 수집 시점                                             |
| ---------------------- | --------------------------------- | ----------------------------------------------------- |
| 닉네임·등급·검증 정답  | `users`                           | 가입, 프로필 변경, 최초 AC 확정                       |
| 오늘의 문제            | `assignments` + `problems`        | 정책 워커 또는 첫 대시보드 조회 시 게시 문제에서 배정 |
| 연속 학습·이번 주 정답 | `solved_problems.accepted_at`     | 문제별 최초 AC 확정                                   |
| 동급 순위              | 같은 등급 `users.verified_solves` | 대시보드 조회 시 계산                                 |
| 최근 채점              | `submissions`                     | 채점 워커가 판정 완료                                 |
| 승급·강등              | `grade_events`                    | 최초 AC 또는 정책 워커의 비활동 정책 적용             |
| 문제 배정              | `assignments`                     | 일일 문제 배정                                        |

## 데이터가 없을 때

1. 오늘의 문제가 없으면 관리자 검수를 통과한 문제를 `PUBLISHED` 상태로 게시한다. 사용자의 등급에 접근 가능한 미풀이·미배정 문제만 후보가 된다.
2. 학습 기록이 없으면 사용자가 실제 코드를 제출하고 채점 워커가 `AC`를 확정해야 한다. 문제별 첫 AC만 `solved_problems`와 검증 정답 수에 반영된다.
3. 승급·강등 기록은 정답 처리 서비스와 정기 정책 워커를 실행해 `grade_events`에 쌓는다.
4. 운영 환경에서는 PostgreSQL, Redis, 채점 워커, 정책 워커를 함께 실행하고 각 워커의 실패율과 큐 적체를 모니터링한다.

## 문제 생성 및 게시 주기

- 생성 워커는 매일 `00:05 KST` 이후 실행되며 수요가 많은 9~4급은 매일 등급별 한 문제를 생성한다.
- 3~2급은 기본적으로 월·수·금에 등급별 한 문제, 1급은 일요일에 한 문제를 생성한다. 주간 기본 생성량은 `9~4급 42개 : 3~2급 6개 : 1급 1개`다.
- 중간 등급 요일은 `GENERATION_MEDIUM_WEEKDAYS_KST`, 1급 요일은 `GENERATION_ELITE_WEEKDAYS_KST`로 바꿀 수 있다. 요일 값은 `0=일요일`부터 `6=토요일`까지다.
- 워커가 정시에 실행되지 못했어도 같은 날 다시 실행되면 누락된 작업을 보충한다. 같은 등급·날짜 작업은 DB 잠금과 결정적 시드로 중복 생성하지 않는다.
- 스키마, 공개·비공개 테스트, 4개 언어 공식답안, 변이·중복·모호성 기준을 모두 통과한 2~9급 문제는 즉시 `PUBLISHED`로 저장된다.
- 1급은 국제 대회 결승 수준의 복합 알고리즘 전용 프롬프트와 AI 공급자만 사용한다. 규칙 기반 쉬운 템플릿으로 폴백하지 않으며 검증에 성공해도 `REVIEW_REQUIRED`로 관리자 검수 대기한다.
- 샌드박스 호스트 오류(`JH`)로 검증이 중단된 일일 작업은 같은 날 인프라가 복구되면 자동 재시도한다. 문제 자체가 검증 기준에 미달한 작업은 자동 재시도하지 않는다.
- 생성 공급자는 기본적으로 `OpenAI → OpenRouter → Ollama → 규칙 기반` 순으로 폴백한다. `GENERATION_PROVIDERS`에서 순서 또는 사용 대상을 변경할 수 있다.
- 9~~6급은 외부 비용과 장애에 의존하지 않도록 규칙 기반 생성기를 먼저 사용한다. 5~~2급은 AI 공급자를 순서대로 시도하고 모두 실패하면 규칙 기반 생성기로 계속 운영한다.
- OpenRouter는 `OPENROUTER_API_KEY`, Ollama는 `OLLAMA_BASE_URL`과 `OLLAMA_MODEL`을 설정한다. OpenAI 키나 크레딧이 없어도 다음 공급자로 자동 전환한다.
- 생성 공급자 오류로 실패한 당일 작업은 워커가 다시 감지해 재생성한다. Redis의 5분 중복 방지 키 때문에 재시도까지 최대 5분이 걸릴 수 있다.
- 실행 시각은 `GENERATION_DAILY_HOUR_KST`, `GENERATION_DAILY_MINUTE_KST` 환경변수로 변경한다.
- 생성 워커는 중단 없이 실행되며 60초마다 스케줄과 누락 작업을 확인한다. Docker 권한은 갖지 않고 내부 `sandbox-runner`에 검증 실행을 요청한다.
- `sandbox-runner`는 외부 포트를 열지 않고 DB·Redis·생성 공급자 키 없이 동작한다. 요청 크기와 언어를 제한하고, 실제 실행 컨테이너는 네트워크·권한·CPU·메모리·프로세스 수를 제한한다.
